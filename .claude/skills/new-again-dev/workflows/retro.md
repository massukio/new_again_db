# Retrospective (mandatory at the end of every task)

1. For everything you changed, find the skill file that describes it and make it
   true again (architecture, design system, workflows, budgets). New kind of
   task → new workflow file + a row in `SKILL.md`'s routing table.
2. Append non-obvious learnings to `knowledge/lessons.md` (what happened, cause,
   rule; promote rules into the relevant file and mark "promoted").
3. Record owner decisions in `knowledge/decisions.md` with date and reason.
4. Prune duplicates; keep files short. Re-read `SKILL.md`.
5. If the change also applies to the sister app autorepair_db, note it for the owner.
6. Commit skill changes with the code. Never put secrets in the skill.
